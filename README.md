# xewe-os-build-toolchain

Build, flash, release and format tooling for ESP32 Arduino projects (C3, C6, S3), kept in
one repository and vendored into each project with `git subtree`.

## Project layout

```
<project>/
├── <project>.ino, Config.h, src/        your firmware
└── build/
    ├── toolchain/                       ← this repository (git subtree)
    ├── release_matrix.csv               project data (committed)
    ├── libraries/required_libraries.txt project data (committed)
    ├── build_config, build_config.ps1   generated by setup (ignored)
    ├── version_state                    generated (ignored)
    ├── .venv/  libraries/*/  builds/    generated (ignored)
    └── .gitignore
```

The toolchain never stores project data, so updating it never touches your matrix,
libraries or build outputs.

## Add to a project

```bash
git clone https://github.com/xewe-labs/xewe-os-build-toolchain ~/code/xewe-os-build-toolchain
~/code/xewe-os-build-toolchain/toolchain.sh add ~/code/my-project
```

`add` runs `git subtree add --squash --prefix=build/toolchain`, creates the project data
templates if they are missing, and commits both. The project needs at least one commit and a
clean working tree.

Projects that still have `build/scripts` and `build/tools` in-tree:

```bash
~/code/xewe-os-build-toolchain/toolchain.sh migrate ~/code/my-project
```

This removes the old copies (one commit), adds the subtree, and keeps `release_matrix.csv`
and `required_libraries.txt`. Re-run setup afterwards so `build_config` is regenerated.

## Update / contribute back

From inside the project:

```bash
build/toolchain/toolchain.sh update                     # pull latest main
build/toolchain/toolchain.sh update --ref v1.2.0        # or a tag
build/toolchain/toolchain.sh status                     # vendored revision + local edits
build/toolchain/toolchain.sh push --branch fix-upload   # send local edits upstream as a branch
```

Use `--url` or `XEWE_TOOLCHAIN_URL` to point at a fork.

## Use

Scripts can be run from any directory; they locate the project from their own path.

```bash
# once per machine/project: arduino-cli, ESP32 core, venv + esptool, libraries, build_config
build/toolchain/scripts/mac/setup_build_environment.sh        # also linux/*.sh and windows/*.ps1

build/toolchain/scripts/mac/build.sh -c c3                    # compile
build/toolchain/scripts/mac/build.sh -c s3 -p /dev/cu.usbmodem1101   # compile + flash + monitor
build/toolchain/scripts/mac/build.sh -c c6 --config_json '{"LED_PIN": "8"}' -n "notes"
build/toolchain/scripts/mac/upload.sh -c c3 -p /dev/ttyACM0   # flash latest build
build/toolchain/scripts/mac/listen_serial.sh -p /dev/ttyACM0
build/toolchain/scripts/mac/release.sh                        # build every matrix row, tag, GitHub release
build/toolchain/scripts/mac/format.sh [--check] [paths...]    # default: <project>/src
```

Linux scripts forward to `scripts/mac`; Windows has PowerShell equivalents (no release script).

`XEWE_BUILD_ROOT` and `XEWE_PROJECT_ROOT` override the default locations (parent of the
toolchain, and parent of that) for projects with a different layout.
